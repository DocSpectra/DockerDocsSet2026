# Question sets

The package has two question sets. Tier 1 is a small set of complex tasks with requirement rubrics. Tier 2 is a larger set of FAQ questions extracted from Docker's documentation. Both are stored with question text separate from every label.

## Tier 2: FAQ questions

### Extraction

The 144 questions are the question headings of Docker's FAQ pages at the pinned commit. They were extracted, not generated. The historical exporter read the 26 FAQ pages in sorted path order and, for each Markdown heading of level 1–6 that ends in `?`, took the heading text as the question and the non-heading lines up to the next question heading, stripped and joined with single spaces, as the reference answer. Pairs with an empty answer were skipped. The exporter also had rules for list-item and title-style questions; none produced a pair in this snapshot. IDs `docker_docs_faq_0001` to `docker_docs_faq_0144` are global sequence numbers in extraction order, so they are tied to this commit and must not be reused for another crawl.

Reference answers keep inline Markdown, Hugo shortcodes and relative links, and lose sub-headings and list structure; they are line-joined Markdown, not rendered text. 23 of the 26 FAQ pages yielded pairs; the three FAQ section index pages yielded none.

[`sources.jsonl`](../questions/tier2/sources.jsonl) ties each question to its FAQ page, heading and line number, with an immutable upstream link to that line. The packager checked every row against the pinned source bytes. The headings have no explicit anchors; `rendered_anchor_approx` is a slug that approximates the documentation site's automatic heading ID and was not checked against rendered pages.

The 26 FAQ pages are excluded from the retrieval corpus and the link graph. Each FAQ page contains its reference answers verbatim, so a corpus that kept them would let a retriever return the question's own source instead of the documentation that explains the answer. The exporter applies this exclusion as a fixed rule; no separate written rationale was recorded with it.

### Populations

| Population | Size | Rule |
| --- | ---: | --- |
| Extracted | 144 | every FAQ heading pair |
| Candidate pool | 142 | historical automatic audit labelled the pair `supported`; `faq_0003` and `faq_0042` were `partially_supported` |
| Freeze | 111 | at least one page verified as supporting in the C2 judgments on the original documentation (qrels v2) |
| Common 105 | 105 | at least one supported page on all four documentation versions (O, S, LT, R0) after whole-page re-judgment (qrels v4) |
| Common 101 | 101 | the same rule on the earlier pool-completion judgments (qrels v3) |

Each population contains the next. [`populations.jsonl`](../questions/tier2/populations.jsonl) records membership and the reason for every exclusion, with supported-page counts per version. The 31 questions dropped at the freeze had no page verified as supporting in the original documentation; they are not duplicate-text drops. The study used the common 105 as its primary tier-2 population and the common 101 as a sensitivity population. The packager recomputed all five populations from the frozen records and compared them with the recorded lists.

The historical audit was a lexical heuristic: a pair was `supported` when enough answer tokens occurred in some corpus page. Its labels define the candidate pool only. They are archived in [`judgments/tier2/historical-automatic/`](../judgments/tier2/historical-automatic/) and are not support judgments.

### Duplicate texts

Five question texts each occur twice, with distinct IDs and source pages (Linux and Mac variants of the same Desktop question, for example). Both IDs are kept. Three of these pairs are in the freeze; the study treated each pair as one cluster when resampling questions. See [`duplicate_text_groups.json`](../questions/tier2/duplicate_text_groups.json).

## Tier 1: complex tasks

### What a task is

Each of the 15 tasks is a realistic multi-step request, such as setting up automated image builds behind passing tests. Each task has four or five core requirements: what a complete answer must do (`requirement`), how to recognize it (`acceptance`), the documentation page that supports it, and, for 48 requirements, one or more verbatim supporting quotations. There are 73 requirements in total. Tier 1 has no reference answers; the requirements are the rubric.

### Generation

All tasks were generated by a language model from exact excerpts of the original documentation, with one prompt and response schema: [`sol-complex-task-prompt-v1.txt`](../protocol/tier1-generation/sol-complex-task-prompt-v1.txt) and [`sol-complex-task-schema-v1.json`](../protocol/tier1-generation/sol-complex-task-schema-v1.json). Each call received two clusters of related pages (a seed page and up to seven linked or related pages) and proposed one task per cluster. Machine gates checked the schema, quotation lengths, exact quotation matches in the page and the number of cited pages.

| Origin | Tasks | Generator | Context |
| --- | ---: | --- | --- |
| September 28 generation, used in an earlier development pilot | 5 | `gpt-6-sol` (Codex CLI, host, read-only sandbox) | 1,263-page historical export |
| September 28 generation, passed the gates but not selected for capacity | 2 | `gpt-6-sol` | same |
| Generated for this study, one per documentation area | 8 | `gpt-6.1-sol`, medium reasoning effort (Codex CLI in a container) | the area's pages in the 1,218-page experiment corpus |

All 42 pages cited by the tasks are in the experiment corpus and are byte-identical in both exports. The submitted prompt and raw response of every generation call are in [`protocol/tier1-generation/`](../protocol/tier1-generation/), and [`provenance.jsonl`](../questions/tier1/provenance.jsonl) joins each task to its call, model, hashes and support pages. The September 28 calls did not record a reasoning effort or Codex CLI version, and no call recorded a model snapshot beyond its model name.

### Author review

The author reviewed all 75 proposed requirements against the cited page text: 63 accepted, 10 marked for revision and 2 rejected. Rejected requirements were removed without replacement, which leaves a gap in the element numbering of two tasks (C1, C2, C3, C5). Eight revised requirements gained supporting quotations from the same page (nine quotations), one acceptance criterion was reworded to the page's wording, and one was left unchanged because the apparent error is in Docker's page. The result is the 73-requirement version packaged here; each requirement records its review decision and note. The initial 75-requirement version is a distinct earlier version and is not included as a question set.

This review covered the requirements. The question wording and the completeness of the support-page lists were not separate review items, and no human graded the answers produced in the study. The five pilot tasks carry no quotations because they were reviewed against the full cited page.
