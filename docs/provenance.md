# Source, scope and identities

## Upstream source

All documentation comes from [docker/docs](https://github.com/docker/docs) at commit `274681c49355bd951ae60c9208e854ff70f12474`, the merge of pull request #24936 on May 1, 2026. Each page in [`manifests/pages-original.jsonl`](../manifests/pages-original.jsonl) carries its repository-relative path and an immutable `https://github.com/docker/docs/blob/274681c…/<path>` link. Rendered `docs.docker.com` URLs are not included: the site's routing was not reconstructed for the pinned commit, and a link to today's live page could show different text.

## Four scopes

The study used four nested views of the same commit. Each has its own identity, and they should not be substituted for one another.

| Scope | Files | Where | Identity |
| --- | ---: | --- | --- |
| Full repository | all files | docker/docs at the commit | Git commit `274681c` |
| Upstream page snapshot | 1,487 | `docs-original:upstream-pages/` | tree `7b54d187fa99f9acc09353f6ae114aa9bfa2579d645df3168c9bc0d2043a9445` |
| Historical export (`repository_root`) | 1,263 pages, 2,496 links | `docs-original:historical-export/` | corpus tree `093304d8ad4e88bfb16dcdee225e8d0587a031f9180574080b7a29e8477eb674` |
| Experiment corpus (`docs_scope_v1`) | 1,218 pages, 2,494 links | `docs-original:documentation/` and `export/` | tree `4c5e0499392bb25dd9641ea191ed3e2fff075bbee27ad798fba6deeff731c43c` |

**Upstream page snapshot.** `git archive` of the commit, keeping files with the suffixes the exporter accepts (`.md`, `.markdown`, `.mdx`, `.rst`, `.txt`, `.html`, `.htm`). The packager compared each file with the Git objects of the commit and found every byte identical. The one exception is `CLAUDE.md`, a Git symlink whose stored content is its target text, `AGENTS.md`.

**Historical export.** The exporter walks the snapshot in sorted path order. It skips any file below a directory whose name starts with an underscore, except `_sources`, which leaves 1,289 pages. A page is an FAQ page if its path matches `*faq*` or any lowercase path component contains `faq`. The 26 FAQ pages supply the tier-2 questions and are left out of the corpus and the link graph, leaving 1,263 pages. A link is a Markdown link (or, in HTML pages, a link target) written in a page and resolved to another corpus page, either as a relative file path or as a documentation-site route such as `/engine/install/`. Image links and self-links are dropped, and repeated links between two pages count once. The link graph does not include links generated by Hugo templates, shortcodes or navigation, so it records the links authors wrote in page text.

**Experiment corpus.** `docs_scope_v1` keeps product and contributor documentation and drops 45 pages written to steer AI agents (`AGENTS.md`, `CLAUDE.md`, `.agents/`, `.github/prompts/` and similar) or to build the site (`layouts/`, `static/`). Removing them also removes 2 links. The original documentation tree `documentation/` holds these 1,218 pages at their repository paths, byte-identical to the snapshot; `export/corpus/` holds the same pages as the retrieval corpus, byte-identical to the corresponding files of the historical export.

## Document IDs and exports

A document ID is the lowercased repository-relative path with its suffix removed and every run of non-alphanumeric characters replaced by `_`, followed by `__` and the first eight hexadecimal digits of the SHA-1 of the lowercased path. For example, `content/manuals/accounts/general-faqs.md` becomes `content_manuals_accounts_general_faqs__428fbe09`. Each export writes one file per page, `<doc_id>.md`, with CRLF line endings, and a `graph_edges.csv` of `source,target` document IDs. The same rule assigns IDs to pages added by the refinements, so an ID never changes meaning between versions.

A tree identity is the SHA-256 of the compact, key-sorted JSON object mapping each POSIX relative path to the SHA-256 of its bytes. It is a content hash of the directory, not a Git commit SHA. The study referred to the documentation versions by opaque variant IDs during answering and scoring; the table joins them to the branches. The sham control S used the original tree and export unchanged, so it shares the `docs-original` branch.

The branch commits were created when the package was built, from the frozen trees. They are packaging commits: they are not commits of docker/docs and do not reproduce the editing history. `docs-lt` and `docs-r0` each have `docs-original` as parent, so `git diff docs-original docs-lt -- documentation/` lists the refinement's changes.

## Per-page lineage

`manifests/pages-<branch>.jsonl` has one row per documentation file with its path, document ID, SHA-256, export file and status relative to the original: `unchanged`, `modified` or `added`. Unchanged pages link to their upstream blob. Modified pages link to the upstream page they were derived from (`derived_from_url`). Added pages were written by the editing agent and have no upstream page, so their upstream link is empty. No page was removed or renamed in either refinement; this agrees with the mapping receipts recorded at each final checkpoint.

The receipts also record where the text units of each changed original page ended up (`moved_content`). This is a content-overlap measurement under the rule `moved_content_majority_v1`, not a record of renames, and should not be read as rename provenance.
